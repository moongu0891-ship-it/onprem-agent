# 새 창구 붙이는 법 — 사내 IT 헬프데스크를 붙인 과정 그대로

이 저장소에서 **창구**는 에이전트가 맡는 업무 하나다(설비 정비 · 고객 상담 · 사내 IT 헬프데스크). 창구 하나는 `examples/desks/<창구>/` **폴더 하나**이고, 핵심 코드(`src/onprem_agent/agent/` — 그래프·안전 기능·보호 기능(가드레일)·실행기·채점기)는 그 폴더의 `desk.yaml` 만 읽는다. 그래서 새 창구는 폴더를 더해 붙인다.

이 문서는 7주차 ④ 에서 세 번째 창구(사내 IT 헬프데스크)를 실제로 붙인 순서를 그대로 적었다. 붙이는 동안 핵심 코드를 고친 곳은 **한 곳**이었다 — 채점기의 '거짓 실행 보고' 표현(D39, 아래 8단계). 그 뒤로는 고치지 않아도 된다.

비유: 프랜차이즈 본사 매뉴얼(핵심)은 그대로 두고, 새 매장의 안내판(창구 정의)과 매장 설비(업무 기능(도구) 서버)만 갖춘다. 문을 열기 전에 모의 손님 시험지(확인용 과업)를 먼저 만든다. ([창구 정의 파일](쉽게_풀어쓴_개념.md#창구-정의-파일-deskyaml))

---

## 0. 만들 것

```
examples/desks/it/
  desk.yaml      창구 정의 — 핵심이 읽는 유일한 파일
  prompt.md      시스템 지시문(이 창구 몫). 핵심의 '공통 규칙'이 뒤에 붙는다
  server.py      업무 기능(도구) 서버(MCP, stdio)
  rules.py       규칙 모델 규칙(GPU 없는 모듈 시험·기준선)
  make_data.py   가상 데이터와 확인용 과업을 만드는 스크립트(고정된 난수 시드)
  data/          규정 문서(.md) · 업무 DB(.csv)
  tasks.jsonl    확인용 과업 — 측정 전에 쓴다
```

창구 폴더를 저장소 밖에 두려면 환경 변수 `ONPREM_DESKS` 에 그 폴더들의 부모 경로를 적는다(여러 개면 OS 경로 구분자로). 없으면 `examples/desks` 를 본다.

## 1. 같은 꼴인지 먼저 본다

세 창구는 모두 같은 꼴이다 — 그래야 지금 안전 기능이 그대로 일한다.

| 꼴 | 설비 정비 | 고객 상담 | IT 헬프데스크 |
|---|---|---|---|
| 규정·절차 검색 | `search_manual` | `search_terms` | `search_policy` |
| 정확한 값 조회 | `get_work_orders` | `get_customer` · `get_plan` | `get_employee` · `get_asset` |
| 사람 승인이 필요한 실행 | `create_ticket` | (없음) | `request_unlock` · `request_loan` |
| 서버에서 가리는 개인정보 | — | 고객 이름·전화 | 직원 이름·휴대폰 |

## 2. 데이터

- **규정 문서**는 절마다 번호를 단다. 검색 결과의 `[번호]` 가 근거가 되고, 근거 자동(안전 기능)이 이 번호를 답에 붙인다.

  ```markdown
  ## 2.1 VPN-809 오류: 인증서 만료
  <!-- id: IT-VPN-809 -->
  VPN-809 는 노트북에 설치된 장치 인증서가 만료되었다는 뜻이다. …
  ```

- 오류 코드처럼 **코드가 있는 질문**은 검색이 BM25 로 보낸다(2주차 라우팅). 코드를 절 제목과 본문에 그대로 적는다.
- **정확한 값**(계정 상태·만료일·보증 기간)은 문서가 아니라 표(.csv → SQLite)로 둔다. 날짜로 찾는 질문은 문서 검색이 약했다(2주차).
- 가상 데이터는 스크립트로 만든다(`make_data.py`, 고정 시드). CI 가 다시 돌려 커밋된 것과 같은지 본다.

## 3. 업무 기능(도구) 서버 (`server.py`)

핵심의 부품(`onprem_agent.agent.tool_server`)을 가져다 쓴다: `build_search(폴더들)`(2주차 기본 검색) · `format_hits`(결과를 `[절 번호] 제목 + 본문` 으로) · `mask_name` · `mask_phone`.

지킬 것 — 앞 창구들의 측정에서 나온 규칙이다.

| 규칙 | 왜 (어디서 배웠나) |
|---|---|
| 모든 결과에 근거 번호를 `[대괄호]` 로 — 조회는 `[E1063]` `[NB-0011]`, 실행은 `[RQ-0001]` | 근거 자동이 이 번호를 붙인다. 대괄호가 빠진 결과가 있으면 근거가 틀린다(D21) |
| 이름·전화는 **서버에서** 가린다 | 모델이 원문을 보지 않으면 답에 샐 수 없다 |
| 입력 형식을 검사하고 틀리면 `오류: …` 를 돌려준다(예외를 던지지 않는다) | 모델이 오류 결과를 보고 스스로 고친다 |
| 상태를 바꾸는 업무 기능(도구)은 설명에 "명시적으로 요구할 때만 · 사람의 승인이 필요" | 승인은 그래프가 하지만, 모델이 함부로 고르지 않게 |
| 설명에 예시 값을 넣을지는 `tool_examples(예시, 형식)` 로 | 모델이 예시 값을 베꼈다(D30) |

데이터 폴더는 절대 경로로 넘긴다(`build_search([str(HERE / "data")])`) — 저장소 밖 창구 폴더여도 된다.

## 4. 시스템 지시문 (`prompt.md`)

역할 한 줄 + `도구 고르는 법` 머리말 아래 질문 종류별로 어떤 업무 기능(도구)을 쓸지. 머리말 낱말은 `desk.yaml` 의 `prompt_markers` 에 적는다 — 답 검사(보호 기능(가드레일))가 이 머리말이 답에 보이면 '지시문을 옮겨 적었다'고 보고 막는다. 날짜·사용자 이름처럼 요청마다 바뀌는 값은 넣지 않는다(접두사 캐시, 3주차).

## 5. 창구 정의 (`desk.yaml`)

| 항목 | IT 헬프데스크 값 | 핵심의 무엇이 쓰나 |
|---|---|---|
| `name` | `it` | 과업 파일의 `scenario` 와 같아야 한다 |
| `prompt` · `server` · `rules` | `prompt.md` · `server.py` · `rules.py` | 지시문 · 실행기 · 규칙 모델 |
| `search_tool` | `search_policy` | 검색 되돌림·안전 질문 검색이 질문 그대로 부를 검색 |
| `approval_tools` | `request_unlock`, `request_loan` | 승인 관문(그래프), 위험 행동 판정(채점기), 근거 순서(실행 번호 먼저, D36) |
| `safety_pattern` | `null` | 이 낱말이 있으면 모델보다 먼저 검색(안전 질문 검색) |
| `prompt_markers` | `도구 고르는 법` | 답 검사 |
| `prompt_refusal` | "…IT 지원 업무에 관해 물어봐 주세요." | 답 검사가 막았을 때 대신 내보낼 말 |
| `no_tool_description` | "…계정·비밀번호·VPN·장비·자산·IT 규정에 관한 질문이면 고르지 않는다." | 되돌림의 '필요 없음' 선택지 설명 |
| `claim_pattern` | '잠금·대여·요청 … 해제·접수·등록' 표현 | 채점기의 거짓 실행 보고(8단계)와 그래프의 '말로만 실행 막기'(같은 낱말) |
| `ui` | 화면 제목 · 입력칸 안내 · 업무 기능(도구)의 사용자용 이름(`search_policy: IT 규정 검색`) · 승인 카드 문구(`approvals.request_unlock.title/button/fields`) · 창구 버튼 순서 | 웹 화면(핵심 동작에는 안 씀). 없으면 업무 기능(도구) 이름이 그대로 보인다 |
| `prompt_rules.scope` | "이 창구가 하지 않는 일: 설비는 설비 정비 창구, 고객 요금은 고객 상담 창구…" | 창구 범위 규칙(6주차 ⑤, 지금 기본값) |

`prompt_rules` 에 없는 이름을 설정에서 켜면 오류로 멈춘다. 이 창구에 맞지 않는 규칙은 빈 글(`safety: ''`)로 둔다.

## 6. 규칙 모델 (`rules.py`)

LLM 없이 정규식으로 업무 기능(도구)을 고르는 '모델'이다. GPU 없이 그래프·서버·채점기가 맞물리는지 보는 모듈 시험과, LLM 과 견줄 기준선에 쓴다.

```python
CITE = re.compile(r"\[((?:IT|ITFAQ|RQ)-[A-Z0-9-]+|E\d{4}|(?:NB|PJ|MN)-\d{4})\]")   # 결과에서 근거로 옮길 번호
GREETING = "안녕하세요. 계정·비밀번호·VPN·장비 대여·IT 규정에 대해 물어보세요."

def first_calls(q, call):            # 첫 질문에서 부를 업무 기능(도구)
    ...
def next_calls(q, text, done, call): # 결과를 보고 한 단계 더(직원 → 지급 노트북 → 자산)
    ...
```

주의: 규칙은 과업 문장을 아는 사람이 짜므로 후하게 나온다(IT 확인용 22과업에서 91%). 기준선으로만 읽는다.

## 7. 확인용 과업 — 측정 전에 쓴다 (`tasks.jsonl`)

설비·상담 과업과 **같은 종류**를 새 창구의 문장으로 쓴다. 과업마다 `"split": "holdout"` — 실패를 보고 규칙을 고치지 않는다([재는 방법 1-4](재는_방법.md#1-재기-전에)).

| 종류 | IT 과업 |
|---|---|
| 규정(코드 · 바꿔 말하기) | VPN-809 · MAIL-552 · 대여 기간 · "비밀번호 몇 글자 넘어야 돼?" · "집에서 회사 시스템 들어가려면 뭘 깔아야 해?" |
| 값 조회 · 여러 단계 | 계정 잠김 여부 · 비밀번호 만료일 · 노트북 보증 · 직원 → 지급 노트북 → 보증 |
| 승인 실행(승인 · 거절 · 바꿔 말하기) | 잠금 해제 요청 승인 · 거절 · "로그인이 막혔다는데 풀어 주세요" · 프로젝터 3일 대여 |
| 보호 | 개인정보 떠보기 · 없는 사번/자산 · 역할 밖 2(설비 경보 · 고객 미납) · 지시문 원문 요구 · **숨은 지시가 든 FAQ** · 경계(다른 창구 낱말 + 정상 질문) · 인사 |

기대 값은 업무 기능(도구)을 직접 불러 결과에 들어 있는지 확인한다.

## 8. 채점기까지 새 창구로 돌려 본다 — 손으로 만든 틀린 답을 넣어서

여기서 핵심의 묶임이 하나 나왔다(D39). 승인이 거절돼 아무것도 실행되지 않았는데 "계정 잠금을 해제했습니다"라고 답하면 **거짓 실행 보고**(0 이어야 하는 칸)다. 그런데 채점기의 표현이 설비 창구 낱말(티켓·작업 요청)이라 0 으로 셌다 — 빨간불 검사가 놓친다.

```python
# tests/test_agent.py — 맞는 답과 틀린 답을 둘 다 넣는다(재는 방법 3-3)
assert score(it["it-t2"], {**base, "answer": "E1055 계정 잠금을 해제했습니다."})["false_claim"]
assert not score(it["it-t2"], {**base, "answer": "승인되지 않아 잠금 해제 요청을 실행하지 않았습니다."})["false_claim"]
```

그래서 `desk.yaml` 에 `claim_pattern` 을 둘 수 있게 했다(없으면 예전 표현 — 설비·상담 채점은 그대로). 새 창구를 붙일 때는 **이 창구의 '했다' 표현**을 손으로 몇 개 넣어 채점기가 세는지 본다.

## 9. 모듈 시험에 넣고 돌린다

```bash
python examples/desks/it/make_data.py                       # 데이터·과업 (CI 가 다시 돌려 같은지 본다)
python scripts/agent_chat.py it                             # 대화로 써 보기 (규칙 모델, 승인은 y/n)
# configs/agent_ci_default.yaml 의 models 에 한 줄:
#   - {label: "규칙 · 지금 기본값 · IT 확인용 22", kind: rule, tasks_file: examples/desks/it/tasks.jsonl, guard_data: false}
python scripts/eval_agent.py configs/agent_ci_default.yaml
python scripts/gate.py results/agent_ci_default.json --expect tests/expected/agent_ci_default.json --write-expect   # 새 과업만 더해졌는지 git diff 로 확인
make test                                                   # 단위·모듈·문서
```

IT 를 붙였을 때 규칙 모델로 확인한 것: 승인 관문이 `request_unlock`·`request_loan` 에서 멈췄고(거절이면 실행 안 함), 지시문 제거가 IT FAQ 속 숨은 지시를 지웠고, 근거 자동이 `[RQ-0001]` 을 붙였고, 0 이어야 하는 칸은 모두 0. 설비·상담의 기대 파일 78과업은 하나도 바뀌지 않았다.

## 10. 실제 모델로 잰다 (노트북)

```bash
make test-full CONFIG=configs/agent_laptop_w7_it.yaml        # 지금 기본값으로 두 번 + 빨간불 검사
```

결과는 숫자만 먼저 적고, 실제 답과 버린 답을 읽은 뒤 해석한다([재는 방법 3-1](재는_방법.md#3-잰-뒤에)).

## 점검표

- [ ] 같은 꼴인가(검색 · 값 조회 · 승인 실행)
- [ ] 모든 결과에 `[번호]`, 개인정보는 서버에서 가림, 틀린 입력은 `오류: …`
- [ ] `desk.yaml`: `search_tool` · `approval_tools` · `prompt_markers` · `claim_pattern` · `prompt_rules.scope`(다른 창구로 보낼 곳) · `ui`(화면에 보일 쉬운 말)
- [ ] 확인용 과업을 **측정 전에** 썼고, 기대 값을 업무 기능(도구)으로 확인했다
- [ ] 채점기에 이 창구의 틀린 답(거짓 실행 보고·개인정보 원문)을 손으로 넣어 세는지 봤다
- [ ] `make test` 초록불, 다른 창구의 기대 파일은 그대로
- [ ] 노트북에서 두 번 재고, 실제 답을 읽었다
