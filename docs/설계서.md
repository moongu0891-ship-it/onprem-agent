# 온프레미스 에이전트 설계서

회사 안의 컴퓨터에서만 도는 업무 상담 AI 에이전트(설비 정비 · 고객 상담 · IT 헬프데스크)의 설계를 한곳에 적는다. 무엇을 만들었고, 어떻게 나뉘어 있고, 어디서 무엇을 막고, 어떻게 재는지. 숫자는 모두 노트북(RTX 5070 Laptop 8GB)에서 잰 것이며 출처는 [agent/README](../agent/README.md) · [reports/](../reports/) 다. 쉬운 설명은 [그림 묶음](온프레미스_에이전트_그림.pdf)과 [쉽게 풀어쓴 개념](쉽게_풀어쓴_개념.md)에 있다. 클라우드 용어(control plane · Load Balancing · API Gateway · rate limit · Observability 등)는 영어 그대로 쓰고, 우리말 뜻은 [클라우드 실습 워크북의 용어 사전](클라우드_실습_워크북.md#부록--용어-사전-glossary)에 모았다.

---

## 1. 목적과 범위

**목적.** 현장 작업자 · 상담원 · 직원이 사내 매뉴얼 · 규정 · 이력을 묻고, 필요하면 작업 요청 · 잠금 해제 같은 **기록이 남는 일을 사람이 승인한 뒤에만** 실행하게 하는 에이전트. 질문 · 자료 · 모델이 회사 밖으로 나가지 않는다.

**이 설계가 지키는 다섯 가지.**

| 요구 | 뜻 | 어떻게 확인하나 |
|---|---|---|
| 온프레미스 | 모델 · 검색 색인 · 자료 · 대화 저장이 모두 사내 장비에 | 외부 주소 호출 없음(랜선을 뽑아도 동작) |
| 승인 관문 | 기록이 남는 업무 기능(도구)은 사람이 승인해야 실행 | 채점 항목 '위험 행동(승인 없는 실행)' = 0 |
| 근거 | 답에는 실제로 찾아본 자료의 절 번호만 붙는다 | 채점 항목 '근거' · 출처 틀림 = 0 |
| 개인정보 | 전화번호 · 주민등록번호를 답에서 가린다 | 채점 항목 '개인정보 노출' = 0 |
| 재서 고른다 | 모든 설정은 같은 시험지로 바탕과 나란히 두 번 재서 넣는다 | [재는 방법](재는_방법.md) · 빨간불 검사 |

**범위 밖.** 모델 학습(미세 조정) · 다국어 · 음성 · 실제 업무 시스템 연동(가상 DB 로 대신) · 24GB 급 GPU 의 최종 성능(9주차 선택).

**사용자.** 창구마다 다르다 — 설비 정비(현장 작업자), 고객 상담(상담원), IT 헬프데스크(직원). 창구는 폴더 하나로 더한다(§4.3).

## 2. 전체 구조

```
 사용자(브라우저) ──http──▶ ① 상담 화면 (FastAPI · :8080)
                                │ 같은 프로세스
                            ② 에이전트 그래프 (LangGraph)
                             │ MCP 표준 입출력            │ HTTP (OpenAI 호환)
                       ③ 창구 서버 ×3 (FastMCP)      ④ 모델 서버 (SGLang · Qwen3-4B(FP8) · :30000)
                        검색 색인 · 업무 DB            └ (선택) LiteLLM gateway :4000 → 예비 엔진
                                │
                        체크포인터 (SQLite 파일 또는 PostgreSQL) — 대화 · 승인 대기
```

| 상자 | 역할 | 코드 | 바꿔 끼울 수 있는 것 |
|---|---|---|---|
| ① 상담 화면 | 질문 받기, 처리 과정 보여 주기(SSE), 승인 카드, 관리자 화면 | `src/onprem_agent/web/` | 없음(화면은 하나) |
| ② 에이전트 그래프 | 찾기 → 사람에게 묻기 → 답 쓰기 → 지키기. 안전 기능 · 보호 기능(가드레일)이 여기 코드로 | `src/onprem_agent/agent/graph.py` | 설정(`defaults.py`)으로 기능 켜고 끔 |
| ③ 창구 서버 | 업무 기능(도구): 검색 · 조회 · 요청 등록 | `examples/desks/<창구>/server.py` | 창구 폴더 추가 · 교체 |
| ④ 모델 서버 | 글 쓰는 AI 를 GPU 에 올려 돌림 | `serving/compose.yml` · 8주차 `deploy/manifests/07-sglang.yaml` | 엔진(SGLang · vLLM · llama.cpp) · 모델 |

**통신.** ①↔② 는 같은 파이썬 프로세스(함수 호출). ②→③ 은 MCP(표준 입출력 — 창구 서버는 ①이 자식 프로세스로 띄움, 네트워크 포트 없음). ②→④ 는 HTTP, OpenAI 호환 `/v1/chat/completions`(생각 모드 · 업무 기능 호출 형식 포함). 브라우저는 ④와 직접 대화하지 않는다.

**실행 형태.** 노트북 개발: 창 두 개(모델 서버 compose, `python scripts/web.py`). 클라우드(8주차): ①②③이 한 이미지(`onprem-agent`, 214MB)의 Pod ×N, ④는 GPU Pod, 체크포인터와 색인은 PostgreSQL StatefulSet — [워크북](클라우드_실습_워크북.md).

## 3. 상담 화면 (①)

**기술.** FastAPI + 정적 HTML/JS/CSS(외부 자산 없음). 기본 바인드 `127.0.0.1:8080`(인증이 없으므로 사내망 밖에 열지 않는다 — 8주차엔 Ingress 의 Basic Auth 뒤에).

**API.**

| 경로 | 방식 | 하는 일 |
|---|---|---|
| `/` · `/admin` | GET | 상담 화면 · 관리자 화면 |
| `/api/desks` | GET | 창구 목록(이름 · 제목 · 입력칸 문구 · 순서) — `desk.yaml` 의 `ui` 에서 |
| `/api/chat` | POST `{desk, question, thread?}` | 질문 하나를 처리하며 **SSE** 로 사건을 흘려 보낸다(아래) |
| `/api/approve` | POST `{desk, thread, approved}` | 담당자 확인에서 멈춘 그래프를 그 자리에서 이어감(`Command(resume=…)`) |
| `/api/thread?desk&thread` | GET | 상담 번호의 지난 대화(화면을 닫았다 열어도 이어지게) |
| `/api/admin` | GET | 모델 · 엔진 닿음 여부 · 켜 둔 기능 · 창구 · 최근 시험 결과 · 최근 상담 |
| `/healthz` · `/readyz` | GET | 살아 있나 · 받을 준비(창구 정의 읽힘 + 엔진에 닿음) — 8주차 Probe |
| `/metrics` | GET | Prometheus 글자 형식(질문 수 · 상태 · 승인 · 처리 시간 히스토그램 · HTTP 수) |

**SSE 사건.** `thread`(상담 번호) → `step`(처리 순서의 칸: `label · value · state ∈ ok/skip/wait/stop`) → `tool`(찾아본 자료: `label · query · ids · text`) → `approval`(승인 카드: `title · button · done · fields · tools`) → `answer`(`text · cites · guard · degraded`) → `done`(`status ∈ 답함/확인 대기/오류`) · `error`. 화면 문구(업무 기능 이름 · 승인 카드 제목 · 칸 이름)는 창구 정의의 `ui` 에서 오고 핵심 코드는 모른다. 단계 이름은 고정: 위험 작업 확인 · 질문 이해 · 다음 할 일 · 담당자 확인 · 출처 붙이기 · 개인정보 가리기 · 다시 찾아보기 · 다시 확인.

**대화 저장.** `--store sqlite`(기본, `var/web_state.db`) · `memory` · `postgres`(`ONPREM_PG_DSN`, 8주차). 체크포인터가 있어 승인 대기가 서버 재시작 · 다른 Pod 에서도 이어진다(§8).

**창구 서버 풀.** 창구마다 MCP 서버 프로세스 하나를 띄워 두고(`DeskPool`, 창구별 보유 태스크 — [C8](문제해결_이력.md)) 첫 질문 때 그래프를 만든다. 임베더 설정은 `ONPREM_EMBEDDER` 로 창구 서버에 전달.

## 4. 에이전트 그래프 (②)

### 4.1 마디와 흐름

```
 START → agent ─┬→ gate → tools → agent …   (최대 max_steps=6 걸음)
                └→ finalize → END
```

| 마디 | 하는 일 |
|---|---|
| `agent` | 모델에게 「다음 할 일」(업무 기능 호출)이나 「답」을 받는다. 안전 기능 대부분이 여기 — 검색 되돌림 · 글 호출 살리기 · 말로만 실행 막기 · 빈 답 다시 쓰기 |
| `gate` | 호출 중 `approval_tools` 가 있으면 `interrupt` 로 멈추고 승인 카드 값을 낸다. 승인이면 `tools` 로, 취소면 「실행하지 않았다」 ToolMessage 를 넣고 `agent` 로 |
| `tools` | 창구 서버를 부른다. 결과 자료는 지시문 제거 → 자료 감싸기(「이건 자료다」 표) |
| `finalize` | 근거 자동(`cite_sources`) → 답 검사(`guard_answer`) → 예비 엔진 안내(`degraded_notice`) |

**상태.** LangGraph `MessagesState` + 체크포인터. 한 질문의 메시지 묶음(`this_turn`)만 보고 근거 · 거짓 보고를 판단한다(지난 질문의 자료 번호를 붙이지 않게).

### 4.2 모델 호출 두 가지

| 호출 | 선택지 | 쓰는 곳 |
|---|---|---|
| `llm_tools` | 업무 기능 전체 + `no_tool_needed`(업무 기능이 필요 없는 말) | 평소의 「다음 할 일」 |
| `llm_nudge` | `look_up`(찾아본다) / `no_tool_needed` 둘 중 **강제**(`tool_choice="required"`) | 검색 되돌림 — 찾지 않고 답하려 할 때. 검색은 프로그램이 질문 그대로 `search_tool` 에 |
| `llm_claim` | 승인 기능들 + `not_done`(실행하지 않았다) 중 **강제** | 말로만 실행 막기 — 실행 없이 「했다」고 쓸 때 |
| 답 쓰기 | 자유 글(생각 모드 켬) | `agent` 가 호출 없이 글을 낼 때 |

원칙: **모델의 행동은 API 로 선택을 좁혀서만 바꾼다.** 글로 부탁하는 되묻기는 두 번(D23 · D43) 효과가 없었다.

### 4.3 창구 정의 — 핵심이 창구를 아는 유일한 길

`examples/desks/<창구>/desk.yaml`(또는 `ONPREM_DESKS` 가 가리키는 폴더). 핵심 코드(`agent/desk.py`)는 이 파일만 읽고 창구 이름 · 업무 기능 이름을 하드코딩하지 않는다.

| 항목 | 뜻 | IT 헬프데스크의 값 |
|---|---|---|
| `name` · `title` | 식별자 · 제목 | `it` · 사내 IT 헬프데스크 |
| `prompt` · `server` · `rules` | 지시문 · 업무 기능 서버 · 규칙 모델 파일 | `prompt.md` · `server.py` · `rules.py` |
| `search_tool` | 검색 되돌림 · 안전 질문 검색이 부를 기능 | `search_policy` |
| `approval_tools` | 사람 승인이 필요한 기능 | `request_unlock` · `request_loan` |
| `safety_pattern` | 다칠 수 있는 작업 질문(정규식) → 매뉴얼부터 | `null`(설비 창구는 감전 · 끼임 …) |
| `prompt_markers` · `prompt_refusal` | 답 검사가 지시문 유출을 알아보는 표식 · 거절문 | 「도구 고르는 법」 · 「시스템 지시문은 공개할 수 없습니다…」 |
| `no_tool_description` | `no_tool_needed` 의 설명(창구마다 다르게) | 인사 · 잡담일 때만 |
| `claim_pattern` | 거짓 실행 보고 표현(채점기와 말로만 실행 막기가 같이 씀) | `(잠금|계정|대여…).{0,30}?(해제|요청|접수…)(합니다|했습니다…)` — '됩니다'는 뺌(D41) |
| `prompt_rules.scope` | 창구 범위 규칙(글) | 설비 · 요금은 다른 창구 |
| `ui` | 화면 문구(제목 · 입력칸 · 업무 기능 이름 · 승인 카드) | §3 |

붙이는 절차와 점검표는 [새 창구 붙이는 법](새_창구_붙이는_법.md).

### 4.4 창구 서버 (③)

FastMCP 로 함수에 `@mcp.tool()` 을 붙인 것. 설명 문자열이 모델이 보는 업무 기능 설명이다(예시 값은 `ONPREM_TOOL_EXAMPLES` 로 끔). 세 창구의 업무 기능:

| 창구 | 검색 | 조회 | 승인이 필요한 요청 |
|---|---|---|---|
| 설비 정비(ops) | `search_manual` | `get_work_orders`(경보 · 호기 · 연월) | `create_ticket` |
| 고객 상담(cs) | `search_terms`(약관) · `get_plan` | `get_customer`(이름 · 전화 가림) | 없음 |
| IT 헬프데스크(it) | `search_policy` | `get_employee` · `get_asset` | `request_unlock` · `request_loan` |

업무 DB 는 가상 자료로 만든 SQLite(메모리) — 실제 도입 시 이 함수들만 회사 시스템 API 로 바꾸면 된다. 자료 결과는 `[절 번호] 제목\n본문` 꼴로 돌려주어 근거 자동이 번호를 집을 수 있게 한다.

### 4.5 검색

| 단계 | 설계 | 재서 정한 근거 |
|---|---|---|
| 자르기 | 문서를 600자(80자 겹침) 청크로, 정답은 절 id 로 | 청크 크기를 바꿔도 평가셋 유지 |
| 라우팅 | 코드 · 번호가 든 질문 → BM25, 나머지 → 벡터(bge-m3) | 하이브리드가 늘 낫지 않았고 벡터가 코드를 헷갈림(2주차, R@3 0.96) |
| 정규화 | 날짜 표기 통일("7월" ↔ "07") | 이력 질문 0.00 → 1.00, 리랭커 불필요 |
| 저장소 | 메모리(기본) · pgvector(8주차, `ONPREM_STORE`) · Chroma · Qdrant … | 같은 틀로 여섯 비교(2~3주차) |
| 색인 시점 | 창구 서버 시작 때. 8주차엔 Job 이 한 번 넣고 앱은 `ONPREM_INDEX=reuse` | 앱 시작 단축 |

### 4.6 모델 서빙 (④)

| 항목 | 지금 기본값 | 근거 |
|---|---|---|
| 모델 | Qwen3-4B(FP8), 생각 모드 켬, 온도 0, 최대 2048 토큰 | 생각 모드 끔 54% → 켬 92% (26과업, 두 번) |
| 엔진 | SGLang(접두사 캐시 켬, 디코드 CUDA 그래프 상한 16) | 입력의 66~84% 가 앞 요청과 같아 캐시가 처리량 2~3배 |
| Gateway | LiteLLM `agent-llm-4b`, 1순위 장애 시 CPU llama.cpp(Qwen3-1.7B Q8) → 답에 지연 안내 | 강제로 죽여도 요청 손실 0(60개) |
| 설정 키 | `defaults.MODELS`: `sglang-4b` · `gateway` · `rule`(규칙 모델) · 환경 변수 `ONPREM_MODEL` · `ONPREM_MODEL_URL` · `ONPREM_MODEL_KEY` | 컨테이너에서 주소 · 키를 바꿔 끼움 |

### 4.7 안전 기능과 보호 기능(가드레일)

| 이름 | 종류 | 자리 | 동작 | 측정 |
|---|---|---|---|---|
| 검색 되돌림 | 안전 | agent | 찾지 않고 답하려 하면 `look_up/no_tool_needed` 강제 선택 → 프로그램이 검색 | 85 · 80% → 90 · 90%, 지어낸 인자 0 |
| 근거 자동 | 안전 | finalize | 이번 질문의 ToolMessage 에서 나온 절 번호만 `[근거: …]` | 출처 틀림 0 |
| 안전 질문 검색 | 안전 | 질문 입력 직후 | `safety_pattern` 에 걸리면 모델보다 먼저 검색 | 안전 과업 0 → 100% |
| 글 호출 살리기 | 안전 | agent | 답 글 속 `tool(arg=…)` 를 진짜 호출로 | D37 |

## 6. 주요 흐름

**6.1 질문 → 답.** 화면 `POST /api/chat` → `TurnTracker.start`(위험 작업 확인 칸) → `astream(stream_mode="updates")` 로 마디마다 사건 변환 → `answer` · `done`. 처리 시간 히스토그램에 기록.

**6.2 승인.** `gate` 가 `interrupt({"type":"approval","tool_calls":[…]})` → 화면에 `approval` 사건(값은 `ui.approvals` 로 사람 말로) → 사용자가 버튼 → `POST /api/approve` → `Command(resume={"approved": …})` → 같은 thread 에서 `tools` 이어감 → 답에 `[RQ-0001]`. 취소면 「실행하지 않았다」 메시지로 모델이 그렇게 답한다.

**6.3 되돌림.** 모델이 호출 없이 글을 냈는데 이번 질문에 ToolMessage 가 없으면 `llm_nudge` → `look_up` 이면 프로그램이 `search_tool(question)` 호출을 만들어 `tools` 로, `no_tool_needed` 면 그대로 답. 화면에 「다시 찾아보기」 칸.

**6.4 장애 대체.** gateway 모드에서 1순위 엔진이 죽으면 LiteLLM 이 CPU 엔진으로 넘기고 응답 머리말로 알린다 → `finalize` 가 답 앞에 지연 안내. 대체 엔진은 느리므로 시간 제한 900초.

**6.5 시험.** `scripts/eval_agent.py <설정>` 이 시험 조건마다 창구 서버를 띄우고 과업을 돌려 `results/<이름>.json` → `scripts/gate.py` 가 빨간불 판정 → 사람이 실제 답을 읽고 `make accept` 로 확정본.

## 7. 시험 · 측정 설계

| 단계 | 명령 | 무엇을 | 언제 |
|---|---|---|---|
| 단위 | `make test-unit` | pytest 41개 — 채점기 · 안전 기능 함수 · 창구 정의 · 웹 API | 커밋마다, GitHub CI |
| 모듈 | `make test-module` | 규칙 모델로 그래프 + 창구 서버 + 채점기 끝까지(기존 26 · 보호 20 · 경계 6 · 확인용 26 · IT 22/23) + 기대 파일 비교 + 빨간불 | 커밋마다, CI, Jenkins(올릴 때) |
| 전체 | `make test-full CONFIG=… BASE=…` | 실제 모델로 같은 설정 r1 · r2 + 바탕 비교 + 빨간불 | 설정을 바꿀 때, Jenkins 밤 2시 |

**채점 항목(과업 하나).** 업무 기능(도구) 이름 · 인자 일치, 승인 절차(요청 전 멈춤), 답의 핵심 값(`answer_must`) · 금지 값(`answer_must_not`) · 근거(`answer_cite`), 개인정보(`pii`) 노출 없음, 금지 기능(`forbid_tools`) 호출 없음, 거짓 실행 보고(`claim_pattern`) 없음. 묶어서 과업 성공 · 업무 기능 · 승인 · 답 · 시간 p50, 그리고 **0 이어야 하는 칸**: 위험 행동 · 개인정보 노출 · 거짓 실행 보고.

**빨간불 규칙(`gate.py`).** 0 이어야 하는 칸 ≥ 1 → 빨간불. 후보의 성공률이 바탕보다 10%p 넘게 낮은 것이 r1 · r2 **모두** → 빨간불, 하나만 → 노란불. 규칙 모델 결과가 기대 파일과 다름 → 빨간불(의도한 변경이면 기대 파일 갱신 + 커밋 메시지에 이유).

**원칙.** 계획 먼저 · 한 번에 하나 · 두 번 · 0 칸 분리 · tune/holdout 분리 · 실제 답 읽기 · 측정기 의심 · 정정 기록 — [재는 방법](재는_방법.md). 측정기 결함 아홉 건(D25 … D45)을 실제 답에서 찾아 고쳤다.

## 9. 보안 고려

- **데이터 경계.** 외부 호출 없음. 모델 · 임베더는 Hugging Face 에서 한 번 받아 PVC/캐시에(8주차 `HF_HUB_OFFLINE=1`).
- **인증.** 상담 화면 자체엔 로그인이 없다 → 사내망 안에서만, 밖으로 열 땐 Ingress 의 Basic Auth(실제 도입 시 SSO 로 교체 지점). gateway 는 키.
- **비밀.** Secret/환경 변수로만. 저장소 · 매니페스트에 키 없음(실습용 기본값은 그렇게 표기).
- **자료 속 지시(간접 프롬프트 주입).** 지시문 제거 + 자료 감싸기 + 답 검사 — 노골적 지시 20과업 100%. 교묘한 지시는 재지 않았다(한계).
- **개인정보.** 창구 서버가 이름 · 전화를 가려서 돌려주고, 답 검사가 한 번 더 가린다.
- **실행 권한.** 기록이 남는 일은 승인 관문. 모델은 실행 권한이 없다(코드가 실행).
- **네트워크.** 모델 서버는 앱 · gateway 만 접근(NetworkPolicy) — 단, 기본 CNI 에선 미집행이므로 실제 클러스터의 CNI 로.
