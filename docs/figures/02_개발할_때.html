실행 순서 — 준비 하나 + 창 두 개

준비 source .venv/bin/activate (한 번) · 모델은 Hugging Face 에서 한 번 받아 둠

① 모델 서버 docker compose -f serving/compose.yml --profile sglang-4b up → 30000번 문

② 상담 화면 python scripts/web.py --model sglang-4b → 8080번 문 (창구 서버 셋은 이게 띄웁니다)

③ 브라우저에서 http://127.0.0.1:8080 · 관리자는 /admin

모델 없이 흐름만 볼 땐 python scripts/web.py (규칙 모델 — 시험 때 쓰는 가짜 AI)

http://127.0.0.1:8080   웹 브라우저 — 사용자가 보는 곳

상담 화면 → 그래프 → 창구 서버 → 모델

① 창구 고르기 · 질문 입력

AI가 처리한 순서: 위험 작업 확인 → 질문 이해 → 잠금 해제 요청 → 담당자 확인

② 승인 카드 → 승인하고 요청 → 답 + [RQ-0001]

여기서 실행되는 것 = 정적 화면 코드

① 주소창 8080 → FastAPI 가 화면 파일(HTML/JS/CSS)을 배달
② 질문은 /api/chat 로 보내고답은 SSE 로 한 사건씩 흘러옴(단계 · 자료 · 승인 카드 · 답)
③ 승인은 /api/approve— 그래프가 멈춰 둔 자리에서 이어감
④ 브라우저는 모델 서버와 직접 대화하지 않음

>_ 창 ① (serving) $ docker compose --profile sglang-4b up sglang-4b Load weight end 4.19 GB sglang-4b Capture cuda graph bs=[1…16] sglang-4b The server is fired up and ready! Uvicorn running on 0.0.0.0:30000 = SGLang · 30000번 문 · Qwen3-4B(FP8)
>_ 창 ② (저장소) (.venv) $ python scripts/web.py --model sglang-4b 상담 화면 http://127.0.0.1:8080/ 관리자 화면 http://127.0.0.1:8080/admin 모델 sglang-4b [창구 서버 ops · cs · it 를 표준 입출력으로 띄움] = FastAPI · 8080번 문 · 그래프 + 창구 서버
>_ 창 ③ (시험할 때) (.venv) $ make test-unit # 15초 41 passed (.venv) $ make test-module # 1분, 규칙 모델 # 빨간불 검사: 초록불 (.venv) $ make test-full CONFIG=… # 1시간, GPU = 시험 세 단계 (그림 6)

포트(port) = 한 컴퓨터 안의 '문 번호'

8080 = 상담 화면   30000 = SGLang(모델)   4000 = LiteLLM gateway(켤 때)   5432 = PostgreSQL(8주차)— 모두 같은 노트북 안입니다.

창구 서버는 문이 없습니다— 상담 화면이 자식 프로세스로 띄우고표준 입출력(MCP stdio) 으로 말합니다.그래서 창구 폴더를 저장소 밖에 두어도(ONPREM_DESKS) 됩니다.

실제 서비스(8주차)에서는 상담 화면 · 모델 서버 · DB 가 서로 다른 Pod 에 있어도 원리는 똑같습니다— 문 번호가 서비스 이름(console · sglang · postgres)으로 바뀔 뿐.
