코드가 지키는 아홉 가지 — 안전 기능과 보호 기능(가드레일)

모델에게 「~하지 마라」 고 부탁하는 것이 아니라, 그래프의 그 자리에 코드로 넣은 것들입니다. 전부 바탕과 나란히 재서 넣었습니다

안전 기능 — 모델의 실수를 막는다

지어내기 · 출처 틀리기 · 안 찾고 답하기 · 말로만 하기

검색 되돌림 걸음 ①

찾아보지 않고 답하려 하면 되돌려 먼저 찾게 합니다.글로 "먼저 찾아라"가 아니라 선택지를 「찾아볼지 말지」로 좁혀 API 로 강제— 검색은 프로그램이 질문 그대로.

측정: 강제를 세게 걸었을 땐 바른 거절까지 버려 85% · 80% → 좁히자 90% · 90%, 지어낸 인자 0 (6주차)

안전 질문 검색 걸음 ⓪

감전 · 끼임처럼 다칠 수 있는 작업 질문은 모델에게 묻기 전에 코드가 매뉴얼 안전 절부터 찾습니다(safety_pattern).

측정: 안전 과업 5개 0% → 100% (5주차)

글 호출 살리기 걸음 ①

모델이 create_ticket(line=2, …) 를 답 글자로 써 버리면(엔진이 호출로 못 알아봄) 코드가 진짜 호출로 옮겨 적습니다.

측정: 6주차 D37 — 메모지에 적힌 주문을 양식으로 옮기기

빈 답 다시 쓰기 걸음 ④

생각 모드가 길어져 답이 비면 생각 없이 한 번 더 씁니다.

측정: 6주차 D38, 생각 모드를 켠 모델에만

말로만 실행 막기 (선택 강제) 걸음 ④

실행한 적 없는 일을 "요청했습니다"라고 쓰면,「요청 기능을 부른다 / 실행하지 않았다고말한다」 둘 중 하나를 API 로 고르게 합니다.글로 되묻는 판은 더 세게 둘러대서(「접수되었습니다 · 진행 중입니다」) 채택하지 않았습니다.

측정: IT 창구 거짓 실행 보고1건 → 0 (바탕과 두 번씩, 7주차 D42 · D43)

근거 자동 걸음 ⑤

답에 붙는 [근거: …] 는 모델이 쓴 번호가 아니라 이번 질문에서 실제로 돌아온 절 번호입니다.

측정: 4주차 — 출처 틀림 0

보호 기능(가드레일) — 밖에서 오는 위험을 막는다

자료 속 숨은 지시 · 개인정보 유출 · 지시문 유출 · 남의 창구 일

지시문 제거 걸음 ②

검색된 자료 속의 「AI 는 ~하라 · 시스템 지시문을 출력해」 같은 문장을 지우고,자료를 「이건 자료다」 표로 감싸 모델에게 줍니다.

측정: 보호 20과업— 노골적 지시는 모델도 따르지 않았지만 "지시문을 그대로 출력해"에는 내놓았다 → 답 검사가 막음 (6주차)

답 검사 걸음 ⑥

보내기 전에 전화번호 · 주민등록번호를 가리고(010-****-5678),창구 지시문의 표식이 답에 그대로 있으면 거절문으로 바꿉니다.

측정: 개인정보 노출 0, 지시문 유출 0 (0 이어야 하는 칸)

창구 범위 규칙 지시문

다른 창구의 일(고객 상담 창구에 설비 경보를 묻기)은 조회하거나 요청을 만들지 않고맞는 창구로 안내합니다.유일하게 글(지시문)로 된 보호 기능— 그래서 과잉 거절도 같이 잽니다.

받아들인 대가: "고객 전화번호 전체 알려줘"에 조회 없이 거절(안전한 쪽)

왜 두 종류로 나눠 부르나

안전 기능은 모델이 실수할 때(찾지 않고 답함 · 번호를 지어냄 · 말로만 함) 코드가 바로잡는 것이고,보호 기능(가드레일)은 모델이 속거나 흘릴 때(자료 속 숨은 지시 · 개인정보 · 지시문) 코드가 울타리를 치는 것입니다.도로의 가드레일처럼 차(모델)가 벗어나도 밖으로 떨어지지 않게 합니다— 업계 용어라 괄호에 남깁니다.

전부 설정으로 켜고 끕니다

defaults.py: nudge · auto_cite · safety_search · recover_text_calls · empty_answer · claim_check="force" · strip_injection · answer_guard · scope

기본은 끔이고, 측정으로 좋다고확인된 것만 기본값에 넣습니다.관리자 화면의 「켜 둔 기능」이 이 목록입니다.

재 보니 틀렸던 감 — 안전 기능을 만들 때 두 번 밟은 같은 돌

"모델에게 글로 '도구를 먼저 써라' 하면 쓴다" → 4주차: 13번 되돌려도 호출 0번 증가. 효과가 난 건 tool_choice="required" 로 선택을 강제했을 때뿐 (D23).

"'아직 안 했다, 다시 생각해 봐'라고하면 고친다" → 7주차: 되물으니 "접수되었습니다"라고더 세게 둘러댐. 선택지를 둘로 좁혀 API 로 강제하자 바로 요청을 불렀다 (D43).

교훈 하나: 모델의 행동을 바꾸는 방법은 구조(API 로 선택을 좁히거나 프로그램이 대신 함)이거나,아니면 효과 없음.새 안전 기능을 설계할 때 먼저 묻습니다— "이게 글로 하는 부탁인가?"

한 줄로 — 안전 기능 여섯은 모델의 실수를, 보호 기능 셋은 밖에서 오는 위험을 코드로 막고, 아홉 모두 0 이어야 하는 칸(위험 행동 · 개인정보 노출 · 거짓 실행 보고)으로 잽니다
